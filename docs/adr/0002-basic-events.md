# 2. Basic Event Data

Date: 2026-08-29

## Status
Accepted

## Context
This helps build out a foundational structure to make further decisions

## Decision
The basic event for communicating with entrance/exit kiosks will consist of 3 fields
 - kiosk_id : which kiosk the card is being tapped at (this also encodes entrance or exit because kiosks are one or the other)
 - card_id : the users card
 - kiosk_transaction_number: number the kiosk tracks of which interaction this is

The server will then create a log-able event from those first two communicated fields and the following fields that the server will assign for help with cataloguing the data.
 - timestamp : when the transaction was performed according to the server (normalization of the data should be handled by the kiosk so double taps or shuffling of the order of events at a similar time will not cause processing problems.
 - event-id : a unique id for tracking the event on the server. this will be generated by the server likely using a hashing function on the kiosk_id, card_id, transaction_number, and server timestamp. 

## Consequences
 - kiosks will be required to be in or out
 - kiosk position tracking will be important in calculating fares
